# WBS Engine — تولید ساختار شکست کار

منبع: `app/engines/wbs.py` · داده: `data/wbs_reference.json` — Issue #7

## چیست
`ScopeSummary` را به `WBS` تبدیل می‌کند: آیتم‌های کاری هر فضا، مرتب‌شده به
ترتیب استاندارد فازها، با وابستگی‌های صریح برای محاسبهٔ مسیر بحرانی.

## توابع
| تابع | نقش |
|---|---|
| `load_reference()` | خواندن `data/wbs_reference.json` (lru_cache) |
| `_items_for_space(space, reference)` | آیتم‌های یک فضا بر اساس فازهای درخواستی |
| `generate(scope)` | WBS کامل مرتب‌شده |

## قواعد مقدار
- `unit: "area"` → مقدار = متراژ فضا × `factor` (کاشی دیوار ×۱٫۸، رنگ ×۲٫۴ …)
- `unit: "fixed"` → مقدار = ۱ و واحد «مورد» (تخریب، نصب سرویس)
- مقدار ≤ ۰ هرگز تولید نمی‌شود

## وابستگی‌ها (`_PHASE_PRECEDENCE`)
هر آیتم به آخرین آیتم فاز قبل **در همان فضا** وابسته می‌شود:

```
demolition(—) → mep → structure → covering → joinery → finish
```

علاوه بر آن، وابستگی‌های درون‌فضایی صریح در JSON (مثل `BAT-JOI-S → MEP-P`)
هم حفظ می‌شوند.

## کدگذاری
`{پیشوند فضا}-{کد آیتم}` → `KIT-COV-T` (کاشی دیوار آشپزخانه). پیشوندها:
KIT/BAT/LIV/BED.

## چرا آیتم‌های هم‌نام بین فضاها ادغام نمی‌شوند
متریال و دستمزد هر فضا متفاوت است (کاشی سرویس ≠ کاشی آشپزخانه) و کارفرما باید
تفکیک هزینه به تفکیک فضا را ببیند. جزئیات: `docs/specs/wbs-reference.md`.

## پوشش‌داده‌شده در تست

و **`test_all_dependencies_reference_existing_items`** (رگرسیون: وابستگی به کد
ناموجود مسیر بحرانی را می‌شکند).
