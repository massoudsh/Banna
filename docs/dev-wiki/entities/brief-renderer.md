# Brief Renderer — سند قابل‌اشتراک با مجری

منبع: `app/engines/brief.py` — Issue #11

## چیست
`RenovationBrief` را به یک HTML فارسی/RTL تبدیل می‌کند که کارفرما می‌تواند
مستقیم برای مجری بفرستد. تولید PDF با تبدیل همین HTML انجام می‌شود؛ موتور PDF
قابل تعویض است.

## توابع
| تابع | نقش |
|---|---|
| `render(brief)` | HTML کامل سند |
| `format_toman(amount)` | «۴۵۰ میلیون تومان» / «۱٫۵ میلیارد تومان» |
| `_scenario_row()` | ردیف جدول مقایسه + نشان «در بودجه»/«بالاتر از بودجه» |
| `_items_rows()` | جدول WBS با فاز، فضا، شرح، مقدار، متریال |
| `_scope_section()` | جدول وضعیت فضاها |
| `_assumptions_section()` | بخش فرض‌ها (اگر فرضی وجود داشته باشد) |

## بخش‌های سند
۱. خلاصهٔ سناریوی انتخابی (بودجه، بازهٔ هزینه، مدت، توصیف)
۲. وضعیت فضاها (متراژ، وضعیت فعلی، کارهای موردنیاز)
۳. مقایسهٔ هر چهار سناریو
۴. فهرست WBS با ترتیب اجرا و متریال پیشنهادی
۵. فرض‌ها و محدودیت‌ها
۶. پانویس عدم‌قطعیت + برندینگ

## نکات امنیتی و صحت
- **همهٔ ورودی کاربر از `html.escape` عبور می‌کند** — رگرسیون XSS در
  `test_escapes_html_in_user_title` پوشش داده شده.
- هزینه همیشه به‌صورت بازه چاپ می‌شود، نه عدد قطعی.
- اگر `selected` در فهرست سناریوها نباشد، اولین سناریو fallback می‌شود
  (نه خطا) — سند نباید به‌خاطر یک فیلد انتخابی از دست برود.
- `render()` بدون هیچ سناریویی `ValueError` می‌دهد.

## چرا متن برای مجری غیرفنی نوشته شده
معیار پذیرش Issue #11: مجری باید **فقط با خواندن Brief**، بدون توضیح اضافه از
کارفرما، scope را بفهمد. به همین دلیل اصطلاحات بازاری به‌کار رفته
(`PHASE_LABELS_FA`) نه واژگان مهندسی. تست این معیار: `docs/specs/acceptance-testing.md` بخش ۵.
