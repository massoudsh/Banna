# Schema — دانش‌نامهٔ توسعهٔ بنّا (Dev Wiki)

> این پوشه دانش‌نامهٔ زنده‌ی **کد** پروژهٔ بنّا است — جدا از `docs/wiki/` که ویکی محصول/کسب‌وکار (مخصوص GitHub Wiki) است.
> هدف: هر ایجنت/توسعه‌دهنده‌ای که بعداً روی این ریپو کار می‌کند، بدون re-scan کل کدبیس، سریع context بگیرد.

## ساختار پوشه
```
docs/dev-wiki/
  schema.md      # همین فایل — قوانین
  overview.md    # یک‌نگاه کلی معماری/وضعیت فعلی (≤۴۰۰ کلمه)
  index.md       # کاتالوگ همه صفحات
  log.md         # تاریخچه append-only
  entities/      # هر entity مهم یک صفحه (مدل داده، سرویس، router، صفحهٔ کلیدی UI)
  concepts/      # patternها، flowها، تصمیم‌های معماری
  sources/        # (اختیاری) خلاصهٔ فایل‌های خام کدی پرارجاع
```

## قانون اکید — وقتی کد تغییر کرد
هر بار تغییر معنایی در کد (مدل جدید، route جدید، امضای تابع تغییر کرد، dependency جدید):
1. تشخیص بده کدام entity/concept تحت‌تأثیر است.
2. صفحهٔ مربوطه را به‌روز کن (یا اگر ≥۳ جای دیگر به آن لینک می‌دهند/concept مستقل بزرگی است، صفحهٔ جدید بساز).
3. یک خط در `log.md`: `## [YYYY-MM-DD] update | <خلاصه>`.
4. تغییرات trivial (typo، فرمت) نیاز به آپدیت ندارند. اگر چند فایل در یک نشست تغییر کرد، آپدیت‌ها را یک‌بار در پایان انجام بده.

## قواعد لینک
- سبک Obsidian: `[[entities/xxx]]` بدون `.md`.
- نام فایل: lowercase + hyphen.

## شروع هر نشست کاری
1. اول `overview.md` و `index.md` بخوان.
2. فقط صفحات مرتبط با تسک فعلی را drill-down کن.

منبع الگو: قالب عمومی «Vault Template» (پیوست پروژه).
