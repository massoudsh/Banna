# بیان مسئله (Problem Statement)

## مسئلهٔ اصلی #057
بازار بازسازی ایران یک کوپایلوت ندارد که پروژه را قبل از شروع قابل فهم، قابل قیمت‌گذاری و قابل اجرا کند — پروژه‌ها با ابهام شروع می‌شوند و با اختلاف ادامه پیدا می‌کنند.

## نقطهٔ شروع تیپیک هر پروژه
بازسازی معمولاً با یک جمله شروع می‌شود:
- «می‌خوام آشپزخونه رو عوض کنم»
- «می‌خوام این خونه قابل اجاره بشه»
- «می‌خوام با کمترین هزینه فضا مدرن بشه»

پشت همین جملهٔ ساده ده‌ها تصمیم پنهان است: چه چیزی تخریب شود؟ چه چیزی بماند؟ تأسیسات نیاز به اصلاح دارد؟ کابینت نو یا بازسازی؟ متریال مناسب چیست؟ چقدر زمان/هزینه می‌برد؟ اول کدام کار انجام شود؟ با این بودجه واقعاً چه سناریویی ممکن است؟

## چرا پرریسک می‌شود؟
بازسازی از وقتی پرریسک می‌شود که پروژه قبل از شروع درست فهمیده نشده باشد:
- کارفرما دقیق نمی‌داند چه می‌خواهد
- مجری باید scope را از صفر بفهمد
- قیمت‌ها قابل مقایسه نیستند
- متریال و کیفیت از ابتدا شفاف نیست
- WBS استانداردی وجود ندارد
- وسط کار تغییرات اضافه می‌شود
- اختلاف بر سر کیفیت، زمان و پرداخت شکل می‌گیرد

## حلقهٔ معیوب

```
Scope مبهم → قیمت غیرقابل مقایسه → تغییر وسط کار → اختلاف → اعتماد کم بین کارفرما و مجری
```

## نکتهٔ کلیدی
مسئله فقط «پیدا کردن پیمانکار» نیست — مسئله این است که **خود پروژه** قبل از اتصال به مجری قابل فهم، قیمت‌گذاری و زمان‌بندی نمی‌شود.
