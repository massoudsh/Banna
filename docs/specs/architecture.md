# معماری فنی بنّا (Technical Architecture)

> مرجع پیاده‌سازی فاز ۱ — Scope & Estimate Copilot (Issueهای #5 تا #13).
> این سند تصمیم‌های پشتهٔ فنی را قفل می‌کند تا موتورها روی یک قرارداد ثابت ساخته شوند.

## ۱. تصمیم پشتهٔ فنی

| لایه | انتخاب | دلیل |
|---|---|---|
| زبان | Python 3.11+ | اکوسیستم AI/OCR/پردازش تصویر، تیم تک‌زبانه با موتورهای داده |
| وب | FastAPI | اعتبارسنجی خودکار، OpenAPI رایگان، async برای آپلود فایل |
| مدل داده | Pydantic v2 | همان مدل‌ها هم برای API و هم برای قرارداد بین موتورها |
| ذخیره‌سازی (MVP) | SQLite + JSON | بدون زیرساخت، کافی برای تست پذیرش؛ مهاجرت به Postgres در فاز ۲ |
| پردازش تصویر | ماژولار با adapter | تشخیص بصری از طریق LLM چندوجهی؛ fallback قاعده‌محور بدون شبکه |
| خروجی PDF | HTML → PDF | قالب فارسی/RTL با فونت ایران‌سنس؛ موتور PDF قابل تعویض |
| تست | pytest | تست موتورها با fixture، بدون تماس شبکه در CI |

### چرا Python و نه TypeScript
موتورهای فاز ۱ عمدتاً **تبدیل داده و محاسبه**اند (Scope → WBS → متریال → هزینه)، نه UI. Pydantic قرارداد بین مراحل را نوع‌دار و قابل‌اعتبارسنجی می‌کند و تست‌های fixture بدون mock پیچیده ممکن می‌شود. فرانت‌اند (Issue #12) در MVP می‌تواند HTML سادهٔ سمت سرور باشد و بعداً مستقل ساخته شود.

## ۲. جریان داده (Pipeline)

```
ورودی کاربر (عکس/ویدیو + متن + متراژ + بودجه + سبک)
        │
        ▼
[#5] media pipeline ──► MediaAsset[]  (اعتبارسنجی، پیش‌پردازش، ذخیره)
        │
        ▼
[#6] scope engine ────► ScopeSummary  (فضاها، وضعیت فعلی، کارهای موردنیاز)
        │
        ▼
[#7] wbs engine ──────► WBS  (فازها به ترتیب استاندارد، آیتم‌ها به تفکیک فضا)
        │
        ▼
[#8] material engine ─► WBS + MaterialSuggestion در هر آیتم
        │
        ▼
[#9] estimate engine ─► Estimate (هزینه + زمان + بازهٔ عدم قطعیت)
        │
        ▼
[#10] scenario engine ► ۴ سناریو: اقتصادی / استاندارد / باکیفیت / اجاره
        │
        ▼
[#11] brief renderer ─► Brief نهایی (HTML/PDF قابل‌اشتراک با مجری)
```

هر مرحله خروجی **ساختاریافته و قابل‌ذخیره** تولید می‌کند؛ بنابراین می‌توان یک پروژه را در میانهٔ pipeline متوقف، بازبینی و از همان نقطه ادامه داد (لازمهٔ «خروجی قابل ویرایش توسط کاربر» در Issue #7).

## ۳. قرارداد بین موتورها

مدل‌های `app/models/` تنها قرارداد مجاز بین موتورها هستند. هیچ موتوری مستقیماً به خروجی خام موتور دیگر وابسته نمی‌شود.

| مدل | تولیدکننده | مصرف‌کننده |
|---|---|---|
| `MediaAsset` | media pipeline (#5) | scope engine (#6) |
| `ScopeSummary` | scope engine (#6) | wbs engine (#7) |
| `WBSItem` / `WBS` | wbs engine (#7) | material (#8)، estimate (#9) |
| `MaterialOption` | material engine (#8) | estimate (#9)، scenarios (#10) |
| `Estimate` | estimate engine (#9) | scenarios (#10)، brief (#11) |
| `Scenario` | scenario engine (#10) | brief (#11) |
| `RenovationBrief` | brief renderer (#11) | خروجی به کاربر |

## ۴. مرز عدم‌قطعیت (Uncertainty)

سه منبع خطا در تخمین، صریح مدل می‌شوند:

1. **خطای تشخیص Scope** (AI عنصر را اشتباه/ناقص تشخیص دهد) — با `confidence` در هر فضای شناسایی‌شده.
2. **خطای قیمت** (بازهٔ بازار) — هر ردیف دیتاست `price_min/price_max` دارد؛ تخمین بازه می‌دهد نه عدد قطعی.
3. **خطای زمان** (بهره‌وری مجری، تأخیر تأمین متریال) — ضریب `duration_factor` با بازهٔ ±.

خروجی نهایی **همیشه بازه** است. عدد قطعی به کاربر نمایش داده نمی‌شود (اصل «صداقت تخمین»).
