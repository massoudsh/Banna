# دیتاست قیمت متریال و دستمزد (Issue #2)

> فایل داده: `data/price_dataset.json` — شهر: تهران، واحد: تومان، تاریخ مرجع: ۱۴۰۵/۰۶.

## ۱. ساختار هر ردیف

```json
"KIT-COV-T": {
  "title": "کاشی‌کاری دیوار آشپزخانه",
  "material": {
    "unit": "مترمربع",
    "tiers": {
      "economy":  { "name": "کاشی ایرانی درجه ۲", "min": 350000, "max": 550000 },
      "standard": { "name": "کاشی ایرانی درجه ۱", "min": 650000, "max": 1100000 },
      "premium":  { "name": "کاشی اسپانیایی/ایتالیایی", "min": 1800000, "max": 3500000 }
    }
  },
  "labor": { "unit": "مترمربع", "min": 280000, "max": 450000 },
  "productivity_m2_per_day": 8
}
```

| فیلد | معنا | قاعده |
|---|---|---|
| `material.tiers.{economy,standard,premium}` | سه سطح کیفی هر آیتم | هر سه سطح **الزامی** است |
| `.min` / `.max` | بازهٔ قیمت واحد | `min > 0` و `min <= max` |
| `labor` | بازهٔ دستمزد اجرا برای همان واحد | دستمزد از متریال جدا نگه داشته می‌شود |
| `productivity_m2_per_day` | مقدار کار انجام‌شده در یک روز | ورودی محاسبهٔ زمان؛ باید > ۰ |

هر سه سطح کیفی اجباری است چون سناریوهای خروجی (Issue #10) هر کدام یک سطح را
کامل مصرف می‌کنند؛ نبود یک سطح یعنی یک سناریو ناقص می‌ماند.

## ۲. چرا بازه و نه عدد قطعی

قیمت بازار ایران در یک روز بین فروشندگان مختلف تفاوت معنادار دارد. ثبت یک عدد
واحد باعث می‌شود تخمین قطعی‌تر از واقعیت به‌نظر برسد. موتور تخمین همیشه بازه
تولید می‌کند و سربار پروژه را روی مجموع بازه اعمال می‌کند.

## ۳. اعتبارسنجی خودکار

تست‌های `tests/test_material.py` این قواعد را روی **همهٔ** ردیف‌ها بررسی می‌کنند:

- `min <= max` و `min > 0` برای هر سه سطح
- `premium.min >= economy.min`
- وجود `labor` و `productivity_m2_per_day > 0`
- پوشش کامل: هر آیتم WBS مرجع باید ردیف قیمت داشته باشد
  (`test_fills_materials_for_all_items` با `missing == []`)

اگر آیتمی قیمت نداشته باشد، موتور آن را **بی‌صدا حذف نمی‌کند**؛ کد آیتم در
`missing_price_codes` برگردانده می‌شود و در متن سند به کاربر اعلام می‌گردد.

## ۴. روش به‌روزرسانی دوره‌ای

1. حداقل سه منبع/فروشنده برای هر آیتم در هر سطح.
2. `min` = کمترین مشاهدهٔ معتبر، `max` = بیشترین مشاهدهٔ معتبر (نه میانگین).
3. تاریخ مرجع در `updated` فایل ثبت شود.
4. پس از هر تغییر، `python3 -m pytest tests/test_material.py` باید سبز بماند.
