# قفل دامنهٔ MVP (Issue #4)

> این سند دامنهٔ فاز ۱ را قطعی می‌کند تا تیم توسعه بدون ابهام کار کند.
> مکمل `docs/wiki/MVP-Scope.md` است (آن سند برای ذی‌نفعان غیرفنی است؛ این سند
> قرارداد فنی).

## ۱. دامنهٔ قطعی‌شده

| پارامتر | مقدار | وضعیت |
|---|---|---|
| نوع پروژه | آپارتمان مسکونی | ✅ قطعی |
| شهر | تهران | ✅ قطعی |
| فضاها | آشپزخانه، حمام/سرویس، نشیمن، اتاق خواب | ✅ قطعی |
| محدودهٔ متراژ | ۲۰ تا ۱۰۰۰ مترمربع | ✅ قطعی |
| واحد پول | تومان | ✅ قطعی |

**دلیل محدودیت متراژ:** زیر ۲۰ مترمربع پروژهٔ بازسازی معنادار نیست (فقط یک
سرویس). بالای ۱۰۰۰ مترمربع وارد دامنهٔ تجاری/اداری می‌شود که خارج از MVP است.
موتور media این محدوده را اعتبارسنجی می‌کند.

## ۲. معیار عددی پذیرش خطای تخمین

پرسش «خطای قابل‌قبول چقدر است؟» در MVP باید عدد داشته باشد، وگرنه تست پذیرش
(Issue #13) قابل‌داوری نیست.

| معیار | آستانه | نحوهٔ سنجش |
|---|---|---|
| خطای میانهٔ تخمین نسبت به quote واقعی | **≤ ۲۵٪** | میانهٔ `abs(تخمین − quote) / quote` روی حداقل ۱۰ پروژه |
| خطای بدترین مورد | **≤ ۵۰٪** | حداکثر انحراف در همان نمونه |
| نرخ پوشش quote واقعی در بازهٔ تخمین | **≥ ۶۰٪** | چند درصد quoteها داخل بازهٔ min–max افتادند |
| ارزیابی کیفی کارفرما | **≥ ۷۰٪ «درست و قابل‌فهم»** | نظرسنجی پس از مشاهدهٔ خروجی |

**چرا ۲۵٪:** در بازار بازسازی ایران، اختلاف quote دو مجری برای *همان* کار
معمولاً بیش از ۲۰٪ است. آستانهٔ سخت‌گیرانه‌تر از این، معیاری می‌سازد که حتی
دو انسان هم آن را پاس نمی‌کنند. عدد نهایی پس از دادهٔ Issue #1 کالیبره می‌شود.

**چرا نرخ پوشش ۶۰٪ و نه ۱۰۰٪:** تخمین عمداً بازهٔ محافظه‌کارانه نمی‌دهد؛ اگر
همیشه ۱۰۰٪ پوشش بدهیم یعنی بازه بی‌معنا پهن شده است.

## ۳. ورودی و خروجی

**ورودی (کارفرما):**
- عکس/ویدیوی فضا (حداقل یکی، حداکثر ۲۵ مگابایت هر فایل)
- توضیح متنی هدف
- متراژ تقریبی
- بودجهٔ تقریبی (اختیاری ولی توصیه‌شده)
- سطح سلیقه/سبک

**خروجی (۶ مورد):** Scope Summary → WBS → Material Suggestions →
Cost & Time Estimate → ۴ سناریو → Brief قابل‌اشتراک.

## ۴. خارج از دامنه (صراحتاً رد می‌شود)

| مورد | فاز هدف |
|---|---|
| شبکهٔ پیمانکار و matching | فاز ۲ (#14، #15) |
| پرداخت/escrow و تأمین مالی | فاز ۴ (#17، #18) |
| پیگیری اجرا و change order | فاز ۳ (#16) |
| پروژهٔ تجاری/اداری بزرگ‌مقیاس | بعد از MVP |
| شهرهای غیر از تهران | بعد از MVP |
| مالکیت چندواحدی و پروژه‌های نوسازی کل ساختمان | بعد از MVP |

اگر کاربری خارج از این دامنه درخواست بدهد، سامانه باید **صریح** بگوید خارج از
دامنهٔ فعلی است — نه اینکه تخمین بی‌کیفیت تولید کند.
